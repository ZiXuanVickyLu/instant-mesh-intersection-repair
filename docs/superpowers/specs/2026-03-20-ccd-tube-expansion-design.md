# CCD-Based Hair Tube Expansion

## Problem Statement

Hair tube meshes are generated by sweeping cross-sections along guide curves,
producing thin tubes (tip_scale ~0.1) that represent individual hair clumps.
These tubes must be expanded to a target scale (~0.8) so adjacent tubes form a
closed shell around the head.  The current optimization-based relaxation
(Laplacian diffusion + gradient descent) is slow, numerically fragile, and
produces self-intersections that require post-processing.

We propose a geometric expansion approach: expand every tube simultaneously from
its centerline outward, using edge-edge Continuous Collision Detection (CCD) to
clamp each edge's expansion at the earliest time of impact.  This is a single
forward pass -- no iterative optimization, no energy minimization, no gradients.

## Definitions

| Term | Meaning |
|------|---------|
| **Guide** | Polyline of L points defining a hair clump's centerline. Fixed throughout expansion. |
| **Layer** | One cross-section ring of N vertices at guide point `guide[li]`. Layer index `li` in `[0, L)`. |
| **Cross-section** | The N-gon swept along the guide. At scale s=0 it collapses to the guide point; at s=1 it reaches the Voronoi boundary polygon. |
| **Connection edge** | An edge connecting vertex `(li, ni)` to vertex `(li+1, ni)` -- i.e., the same cross-section index across adjacent layers. These are the edges that define the tube's longitudinal structure. |
| **Ring edge** | An edge connecting vertex `(li, ni)` to `(li, (ni+1) % N)` within the same layer. |
| **TOI** | Time Of Impact -- the parameter `t in [0, 1]` at which two swept edges first touch during expansion. |
| **Body mesh** | Watertight mesh of the character body. All tube geometry must stay outside this surface. |
| **Wrapper mesh** | Watertight mesh enclosing the valid hair volume. All tube geometry must stay inside this surface. |

## Tube Geometry Recap

From `_build_tube_mesh` in `standalone_voronoi_tube.py`:

- **Vertex count**: `L * N + 1` (L layers of N vertices + 1 tip center)
- **Vertex indexing**: layer `li`, vertex `ni` -> index `li * N + ni`
- **Tip vertex**: index `L * N`, always positioned at `guide[-1]` (zero displacement during expansion)
- **Layer 0**: placed at the actual 3D Voronoi boundary polygon on the scalp.
  At generation time, layer 0 has `scale = 1.0` (full boundary size).
  **Layer 0 vertices are pinned during expansion** -- they are already at full
  scale and anchored to the scalp surface.
- **Layers 1..L-1**: cross-section scaled by
  `scale(li) = 1.0 + (li/(L-1)) * (tip_scale - 1.0)` where `tip_scale` is
  the generation parameter (e.g. 0.1). Each layer has a different current scale:
  layer 0 is at 1.0, layer L-1 is at `tip_scale`.
- **Face connectivity**: between layers li and li+1, for each cross-section edge ni:
  ```
  a = li*N + ni,      b = li*N + (ni+1)%N
  c = (li+1)*N + ni,  d = (li+1)*N + (ni+1)%N
  triangles: [a,c,b], [b,c,d]
  ```
- **Tip cap**: fan of N triangles from last-layer ring to tip vertex

## Algorithm Overview

### Input

1. `tube_meshes`: list of `(verts, faces)` pairs from `build_tube_meshes`
2. `guides`: list of L-point polylines (the centerlines)
3. `n_cross` (N): cross-section vertex count (auto-detected or specified)
4. `target_scale`: desired expansion ratio (default 0.8)
5. `current_scale`: the tip_scale used during generation (default 0.1)
6. `body_mesh_path`: path to body mesh OBJ (stay-outside boundary)
7. `wrapper_mesh_path`: path to wrapper mesh OBJ (stay-inside boundary)

### Output

1. Expanded `tube_meshes` with per-edge clamped scale factors
2. Resampled centerlines (centroid of each layer's cross-section ring)

### High-Level Steps

```
1. Parse tube topology -> extract per-tube layers, connection edges, ring edges
2. Compute expansion vectors for every vertex (per-layer scale):
     For layer li:
       current_s = 1.0 + (li/(L-1)) * (current_scale - 1.0)
       target_s  = 1.0 + (li/(L-1)) * (target_scale - 1.0)
     v_start = guide[li] + current_s * (v_boundary[li,ni] - guide[li])
     v_end   = guide[li] + target_s  * (v_boundary[li,ni] - guide[li])
   Layer 0: pinned (current_s = target_s = 1.0, no motion)
   Tip vertex: pinned (always at guide[-1])
3. Encode each edge as two swept triangles; build BVH over swept triangles
4. For every edge pair from DIFFERENT tubes (broad-phase from BVH):
     Run edge-edge CCD to find TOI
5. For every tube edge vs body_mesh:
     Run vertex-triangle + edge-edge CCD (must stay outside body)
6. For every vertex vs wrapper_mesh:
     Signed-distance containment check (must stay inside wrapper)
7. Per-edge clamping: each edge's expansion is limited to
     min(TOI) * (1 - epsilon) across all collisions
8. Propagate clamped scales to vertices (each vertex takes min of its incident edges)
9. Apply final positions
10. Resample centerlines as layer-wise centroids
```

## Detailed Design

### 1. Expansion Parameterization

Each layer has its own current and target scale, determined by the generation
formula from `_build_tube_mesh`:

```
scale(li) = 1.0 + (li / (L-1)) * (s - 1.0)
```

where `s` is the scale parameter. At generation (`s = tip_scale = 0.1`):
- Layer 0: scale = 1.0 (full boundary)
- Layer L-1: scale = 0.1 (near centerline)

At target (`s = target_scale = 0.8`):
- Layer 0: scale = 1.0 (unchanged)
- Layer L-1: scale = 0.8

Only layers where `current_s < target_s` need expansion. Layer 0 is always
pinned since its scale is 1.0 at both current and target.

For each non-pinned vertex, the motion is linear:

```
v(t') = v_start + t' * (v_end - v_start)     t' in [0, 1]
```

where:
- `v_start` = current position at `current_s`
- `v_end` = target position at `target_s`
- `t' = 0` -> vertex at current position
- `t' = 1` -> vertex at target position

This linear motion defines a swept quadrilateral for each edge: the two
endpoints each trace a line segment, and the edge sweeps from its start
configuration to its end configuration.

### 2. Edge Classification and Extraction

From the tube topology, extract three classes of edges:

**Connection edges** (longitudinal): `(li*N + ni) -- ((li+1)*N + ni)` for each
layer pair and each cross-section vertex.  Count per tube: `(L-1) * N`.

**Ring edges** (circumferential): `(li*N + ni) -- (li*N + (ni+1)%N)` for each
layer.  Count per tube: `L * N`.

**Tip edges**: `((L-1)*N + ni) -- L*N` for each cross-section vertex.  Count
per tube: `N`.

**Total edges per tube**: `(L-1)*N + L*N + N = 2*L*N`.

For CCD purposes, we test all edges from **different tubes** against each other.
Intra-tube self-intersection is excluded: the parallel-transport frame
construction and the linear scaling from centerline ensure that a single tube's
cross-sections do not self-intersect during expansion. High-curvature guides
could theoretically cause intra-tube collisions, but in practice the
cross-section radii (~0.01-0.05 units) are much smaller than guide bending
radii (~0.5+ units), making intra-tube CCD unnecessary. If needed in the
future, intra-tube CCD can be added with adjacency filtering (skip edge pairs
sharing a vertex or within topological distance <= 2).

### 3. Edge-Edge CCD (ACCD)

We use **Additive CCD (ACCD)** instead of solving the cubic coplanarity
polynomial directly. ACCD is an iterative advancement method that is more
robust to degenerate configurations (parallel edges, near-zero motion,
co-linear vertices) and avoids the numerical issues of cubic root finding.

Given two edges `(a0, a1)` and `(b0, b1)`, each endpoint moving linearly:

```
a0(t) = a0_start + t * (a0_end - a0_start)
a1(t) = a1_start + t * (a1_end - a1_start)
b0(t) = b0_start + t * (b0_end - b0_start)
b1(t) = b1_start + t * (b1_end - b1_start)
```

**ACCD algorithm outline**:

1. Start at `t = 0`
2. Compute the current minimum distance `d(t)` between the two edges using
   the **warp** closest-point primitive (see Section 3a)
3. Compute an upper bound on the relative velocity `v_max` of the two edges
4. Advance `t` by a safe step: `dt = d(t) / v_max`
5. If `t + dt >= 1`, the edges are collision-free -> return TOI = infinity
6. Otherwise, set `t += dt` and repeat from step 2
7. If `d(t) < epsilon`, a collision is detected -> return TOI = t

ACCD guarantees no false negatives (missed collisions) and converges in
`O(1/epsilon)` iterations. It is well-suited for GPU batching since each
edge pair's iteration is independent.

Apply a safety margin: clamp at `toi * (1 - eps)` where `eps = 1e-6` to
prevent floating-point micro-penetrations at exact contact.

### 3a. Closest-Point Queries (Warp)

The ACCD algorithm requires computing the minimum distance between two edges
(edge-edge) and between a point and a triangle (vertex-triangle). We use
**warp** for these closest-point primitives:

- **Edge-edge closest point**: Given edges `(a0, a1)` and `(b0, b1)`, warp
  computes the closest pair of points and returns the squared distance.
  This handles all degenerate cases (parallel edges, zero-length edges).

- **Vertex-triangle closest point**: Given a point `p` and triangle
  `(t0, t1, t2)`, warp computes the closest point on the triangle and
  returns the squared distance. Handles edge/vertex projections correctly.

The warp implementation will be provided at implementation time. It provides
differentiable, GPU-accelerated geometric primitives.

### 4. Edge-Triangle CCD (Body Mesh Boundary)

For each tube edge expanding outward, test against triangles of the body mesh
(static). We use the same ACCD advancement approach:

**4a. Vertex-Triangle ACCD**: For each moving vertex `v(t)`, iteratively
advance using warp's vertex-triangle closest-point distance as the safe step
bound. The vertex must not penetrate the body mesh surface.

**4b. Edge-Edge ACCD**: For each moving tube edge `(a(t), b(t))`, test against
each static triangle edge `(p_i, p_j)` using ACCD with warp's edge-edge
closest-point distance. Since the body mesh edges are static, the relative
velocity bound simplifies (only the tube edge moves).

Both sub-tests contribute TOIs that clamp the tube edge/vertex expansion.

Since the body mesh is static and watertight, we build a separate BVH over body
mesh triangles and query it with the swept AABB of each tube edge.

### 5. Wrapper Mesh Containment

All expanded vertices must remain inside the wrapper mesh.  For each vertex:

1. Compute the target position `v_end`
2. Compute signed distance from `v_end` to wrapper mesh (negative = inside)
3. If `v_end` is outside (signed distance > 0):
   a. Binary search along the ray `v_start -> v_end` with 20 iterations
      (tolerance ~1e-6 of the ray length)
   b. At each midpoint, check signed distance to wrapper
   c. Find the maximum `t` where the vertex is still inside
4. Record `toi_wrapper[v]` for this vertex

**Order of operations**: Wrapper containment produces per-vertex TOIs. These
are applied to vertex expansion limits *before* the per-edge reduction in
Section 6. Specifically:

```
t_vertex[v] = min(toi_wrapper[v],
                  min over incident edges e of toi_min[e])
```

### 6. Per-Edge TOI Clamping

Each edge `e` accumulates TOIs from all CCD tests (inter-tube + body mesh):

```
toi_min[e] = min over all collision partners of TOI(e, partner)
```

The edge's expansion is clamped to `toi_min[e] * (1 - eps)`.  To convert to
vertex positions, each vertex takes the minimum clamped expansion of all its
incident edges AND its wrapper containment TOI:

```
t_vertex[v] = min(toi_wrapper[v],
                  min over incident edges e of toi_min[e])
```

This guarantees no edge exceeds its collision-free expansion range.

### 7. Propagation and Smoothing

The single-pass CCD tests all edges assuming full expansion from `v_start` to
`v_end`. When a vertex gets clamped (e.g., a ring edge at layer 0 clamped at
`t=0.3`), connection edges sharing that vertex are tested against their full
trajectory but will only expand their shared endpoint to `t=0.3` due to the
vertex-minimum reduction. This is conservative: the connection edge CCD may have
allowed more expansion, but the vertex is already constrained by another edge.

This conservatism is acceptable -- it may slightly under-expand some regions but
guarantees collision-free results. No multi-pass refinement is needed.

**Optional post-CCD smoothing**: If adjacent layers have very different
expansion ratios, the tube surface becomes jagged. A 1D smoothing pass along
the guide direction can mitigate this:

```
for each tube:
    for each cross-section vertex ni:
        collect t_vertex along layers: [t[0,ni], t[1,ni], ..., t[L-1,ni]]
        apply 1D Laplacian smoothing
        CLAMP: smoothed values must be <= original CCD-clamped values
               (smoothing can only DECREASE expansion, never increase)
```

### 8. BVH Acceleration

The existing CUDA BVH in `externals/torch-mesh-isect/` operates on triangles
and returns triangle-triangle collision pairs. It does **not** natively support
edge-edge queries. We adapt it as follows:

**Approach: Encode swept edges as triangle pairs.**

Each edge sweeping from `(a_start, b_start)` to `(a_end, b_end)` traces a
quadrilateral. Encode this quad as two triangles:

```
tri_0 = (a_start, b_start, a_end)
tri_1 = (b_start, b_end, a_end)
```

Feed all swept-edge triangles into the existing triangle-triangle BVH. The BVH
returns colliding triangle pairs. From each colliding pair, recover the original
edge pair and run ACCD (Section 3) as narrow-phase.

This avoids writing a new BVH. The triangle count doubles (2 triangles per
edge), but the BVH handles this efficiently.

**max_collisions**: Set to 64. Note: the CUDA extension may have a compile-time
`MAX_COLLISIONS` constant. If the current build uses a lower value (e.g., 16),
the CUDA source must be recompiled with `MAX_COLLISIONS=64`. Overflowed
collision buffers silently drop pairs, producing incorrect results.

**Body mesh BVH**: Build a separate BVH over body mesh triangles (static).
Query with swept-edge AABBs of tube edges.

For each tube edge, the swept AABB encloses all 4 points:

```
aabb(e) = bounding_box(a_start, b_start, a_end, b_end)
```

### 9. Centerline Resampling

After expansion, the guide curves no longer pass through the centroid of each
layer's cross-section (because per-edge clamping may have asymmetrically
constrained different sides of the tube).

Resample centerlines:

```
for each tube, for each layer li:
    new_center[li] = mean of vertices [li*N + 0, li*N + 1, ..., li*N + N-1]
```

This produces the final guide curves that are consistent with the expanded tube
geometry.

## Data Flow

```
tube_meshes (from build_tube_meshes)
    |
    v
[Parse topology] -> per-tube layers, edges, vertex-to-guide mapping
    |
    v
[Compute per-layer expansion vectors] -> v_start, v_end for every vertex
    |                                     (layer 0 + tip pinned: v_start = v_end)
    v
[Encode swept edges as triangle pairs] -> 2 triangles per edge
    |
    v
[Build BVH] over swept-edge triangles
    |
    v
[Broad-phase] -> candidate triangle pairs (different tubes only)
    |
    v
[Recover edge pairs from triangle pairs]
    |
    v
[Narrow-phase ACCD (edge-edge)] -> per-edge TOI from inter-tube collisions
    |
    v
[Body mesh BVH query] -> candidate tube-edge vs body-triangle pairs
    |
    v
[ACCD vs body (vertex-tri + edge-edge)] -> per-edge TOI from body
    |
    v
[Wrapper signed-distance check] -> per-vertex TOI from wrapper bounds
    |
    v
[Reduce] -> per-vertex t = min(wrapper TOI, min incident edge TOIs)
    |
    v
[Apply safety margin] -> t *= (1 - eps)
    |
    v
[Optional: longitudinal smoothing of per-vertex t (decrease only)]
    |
    v
[Apply positions] -> v_final = v_start + t * (v_end - v_start)
    |
    v
[Resample centerlines] -> layer-wise centroids
    |
    v
expanded tube_meshes + new centerlines
```

        vertex_tri_accd(vs, ve, p0, p1, p2) -> toi

## Reusable Components

1. **BVH** from `externals/torch-mesh-isect/` -- triangle-triangle broad-phase.
   Adapted for edge CCD by encoding swept edges as triangle pairs. May require
   recompilation with `MAX_COLLISIONS=64`.
2. **Parallel transport frames** from `standalone_voronoi_tube.py` -- already
   used for tube generation, needed for computing full-scale boundary positions
3. **Tube topology parsing** -- new, but trivial given the known vertex indexing
   scheme (`li * N + ni`)
4. **trimesh** for loading body/wrapper meshes and signed-distance queries

## Edge Cases

1. **Zero-length guide segments**: `_parallel_transport_frames` already handles
   this by copying the previous frame.  Expansion vectors will be zero,
   effectively freezing those layers.

2. **Tubes with no collisions**: expand to full `target_scale` unclamped.

3. **Tubes entirely inside body mesh at start**: should not occur if tube
   generation is correct; flag as error.

4. **Wrapper mesh is None**: skip containment check, only enforce body mesh and
   inter-tube CCD.

5. **Body mesh is None**: skip body penetration check.

6. **Degenerate configurations (parallel edges, etc.)**: ACCD handles these
   naturally -- warp's closest-point returns a valid distance even for
   degenerate edge configurations, and ACCD advances safely past them.

7. **Tip vertex**: always at `guide[-1]`, zero displacement. Tip edges from
   last ring to tip vertex are included in CCD; only the ring-side endpoint
   moves during expansion.

8. **Layer 0 vertices**: pinned at full boundary scale (1.0). They do not
   participate in expansion but their edges are still included in CCD tests
   as static obstacles for other tubes.

## Performance Considerations

- **Edge count**: ~330 tubes, each ~20 layers, ~12 cross-section verts =
  ~330 * 2 * 20 * 12 = ~158,400 edges.  Encoded as ~316,800 swept triangles
  for BVH input.
- **BVH capacity**: The existing BVH handles meshes with ~100K+ triangles.
  ~317K swept triangles is larger but feasible with `max_collisions=64`.
- **CCD narrow-phase**: ACCD iterative advancement per candidate pair.
  GPU-parallelizable since each pair's iteration is independent. Warp
  closest-point queries are GPU-native.
- **Single pass**: no iteration, no convergence criteria.  Wall time is
  dominated by BVH build + CCD queries.
- **Memory**: per-edge TOI array + vertex positions + swept triangle buffer.
  No large matrices or Cholesky factors.

## Testing Strategy

1. **Unit test CCD solver**: known edge pairs with analytically computable TOI
2. **Two-tube test**: two tubes facing each other, verify expansion stops at
   contact
3. **Body mesh test**: single tube expanding toward a plane, verify it stops
4. **Wrapper test**: single tube in a box, verify containment
5. **Full pipeline**: 330 tubes, visual inspection with Polyscope
